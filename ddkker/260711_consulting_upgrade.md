# 딸깍테크닉 기능 제안서 — 외주 의뢰 접수 채널

- **작성일:** 2026-07-11
- **대상 사이트:** ddkker.com (딸깍테크닉)
- **제안 범위:** 크몽·재능넷·위시캣·숨고 유입을 자사 사이트로 모으는 외주 의뢰 접수·관리 채널 신설

---

## 1. 요약 (Executive Summary)

크몽·재능넷·위시캣·숨고에서 들어오는 외주 문의를 **자사 사이트(ddkker.com)로 모아 한 곳에서 관리**하는 채널을 신설한다. 4개 플랫폼은 외부에서 일감을 자동으로 가져올 공개 API가 없으므로, 본 제안은 **① 사이트 내 의뢰 접수구 + ② 허용 범위 내 플랫폼 → 사이트 유입 + ③ 유입경로 태깅·파이프라인 관리**로 구성한다.

기존 커뮤니티 글쓰기 흐름과 관리자 목록 패턴을 재사용하므로 **신규 개발 부담이 작고**, 1단계(접수폼+관리자 보드)를 먼저 배포한 뒤 2단계(카카오톡 알림)를 붙이는 단계적 도입을 권장한다. 단, 플랫폼별 외부 링크 허용 정책과 개인정보 처리 고지는 1단계 착수 전에 확정한다.

**확정된 방향**
- 범위: 접수폼 + 관리자 보드 (+ 랜딩에 허용 범위 내 플랫폼 프로필 링크 노출)
- 접수: 로그인 필수
- 알림: 카카오톡 "나에게 보내기" (2단계 분리)
- 플랫폼 정책: 외부 링크 허용 위치 확인 후 적용, 불가 시 수동 유입경로 태깅으로 대체
- 개인정보: 연락처 수집 목적·보유기간 고지 및 처리방침 반영

---

## 2. 배경과 문제

- 현재 외주 문의는 크몽·재능넷·위시캣·숨고 **각 플랫폼 앱/메시지로 흩어져** 들어와, 한눈에 파악·관리하기 어렵다.
- 어떤 플랫폼이 실제 계약으로 이어지는지 **유입경로별 성과 추적이 안 된다.**
- 상담 → 견적 → 계약 → 완료로 이어지는 **진행 상태 관리 도구가 없다.**

## 3. 핵심 전제 및 한계 (반드시 인지)

- **자동 수집 불가:** 크몽·재능넷·위시캣·숨고 모두 외부 앱이 일감·메시지를 끌어올 공개 API를 제공하지 않는다. 따라서 본 채널은 **"인바운드 유입 + 유입경로 태깅"** 까지만 다룬다. (플랫폼 알림 메일을 한 계정으로 모아 파싱하는 방식은 별도 검토 사항이며 본 제안 범위 밖)
- **플랫폼 정책 제한:** 플랫폼 프로필/소개/게시물에 외부 URL·연락처를 직접 기재하는 것이 제한될 수 있다. 실제 반영 전 각 플랫폼의 허용 위치를 확인하고, 허용되지 않는 플랫폼은 관리자 보드에서 수동으로 유입경로를 지정한다.
- 각 플랫폼에서 허용되는 위치에는 **내 사이트로 오는 링크(`?source=kmong` 등)를 걸어** 유입을 유도하고, 접수 시 그 경로를 자동 태깅한다.
- **로그인 전환 경로 보존:** 접수는 로그인 필수이므로, 미로그인 사용자가 `/auth/login?next=/outsourcing/new?source=...` 흐름으로 이동한 뒤 원래 유입경로를 잃지 않고 복귀해야 한다. 필요하면 `source`를 단기 쿠키에도 저장한다.
- **개인정보 처리:** 이름·이메일·전화번호·프로젝트 상세를 받으므로 수집 목적, 보유기간, 선택 항목, 삭제/마스킹 기준을 개인정보처리방침과 접수폼에 반영한다.

## 4. 제안 기능 상세

### 4-1. 공개 랜딩 페이지 `/outsourcing`
- 제공 서비스 소개, 진행 프로세스, 대표 실적/후기(선택), **허용 범위 내 플랫폼 프로필 링크**, "의뢰하기" CTA.
- 플랫폼별 외부 링크 허용 여부가 확인되지 않은 경우 해당 링크는 자리표시자로 두거나 숨긴다.
- 플랫폼에서 넘어온 방문자가 신뢰를 갖고 바로 문의하도록 설계하되, 플랫폼 약관을 우회하는 문구는 넣지 않는다.

### 4-2. 외주 의뢰 접수폼 `/outsourcing/new` (로그인 필수)
- 입력: 제목, 프로젝트 유형, 예산대, 희망 일정, 상세 설명, 연락처(이름·이메일 자동 채움 + 전화 선택), **유입경로**(기본 direct, 플랫폼 링크로 오면 자동 세팅), 개인정보 처리 고지 확인.
- 미로그인 시 로그인 페이지로 유도하되, `next` 파라미터 또는 단기 쿠키로 `/outsourcing/new?source=...` 복귀와 유입경로 보존을 보장한다.
- 스팸 방지를 위한 요청 제한(rate limit) 적용. 개인정보처리방침 링크와 연락처 보유기간 안내를 폼 하단에 노출.

### 4-3. 관리자 파이프라인 보드 `/admin/inquiries`
- 의뢰 목록(최신순), **상태 관리**: 신규 → 상담 → 견적 → 계약 → 완료 / 보류.
- **유입경로 필터**(크몽/재능넷/위시캣/숨고/직접)로 플랫폼별 성과 파악.
- 플랫폼 외부 링크 유입이 불가능한 경우를 대비해 관리자가 유입경로를 수동 보정할 수 있게 한다.
- 관리자 메모, 상태 변경 이력(감사 로그) 기록.
- 관리자 대시보드에 "미처리 의뢰 수" KPI + 최근 의뢰 5건 추가.

### 4-4. 카카오톡 알림 (2단계)
- 새 의뢰가 접수되면 관리자에게 **카카오톡 "나에게 보내기"** 로 즉시 요약 알림.
- 선행 설정이 필요해 1단계 배포 후 별도로 붙인다(아래 로드맵 참조).

## 5. 데이터 모델 (신규 테이블)

`supabase/migrations/009_project_inquiries.sql` — 기존 컨벤션(BIGSERIAL PK, TEXT+CHECK 상태값, created/updated_at, RLS) 그대로 미러링.

| 컬럼 | 설명 |
|---|---|
| `id` | BIGSERIAL PK |
| `user_id` | 접수자(로그인 필수). `UUID NULL REFERENCES profiles(id) ON DELETE SET NULL`로 두어 탈퇴 시 의뢰는 보존 |
| `contact_name / contact_email / contact_phone` | 연락처(전화 선택) |
| `project_type` | web / app / automation / ai / data / design / etc |
| `budget_range` | 100만 미만 ~ 1000만 초과 / 미정 |
| `timeline` | 희망 일정(자유 입력) |
| `title / description` | 제목·상세(길이 검증) |
| `source` | kmong / talentnet / wishket / soomgo / direct / other. 자동 태깅 실패 시 사용자 선택 또는 관리자 보정 |
| `status` | new / contacted / quoted / contracted / done / dropped |
| `admin_note` | 관리자 메모 |
| `privacy_ack_at / privacy_notice_version` | 접수 당시 개인정보 처리 고지 확인 시각·버전 |
| `created_at / updated_at` | 타임스탬프 |

- **보안(RLS):** 접수자는 본인 의뢰만 조회·생성(`auth.uid() = user_id`), 관리자는 전체 조회·수정. 상태/메모/유입경로 보정은 서버(서비스 롤)에서만 처리. `user_id`가 NULL인 행은 탈퇴 후 보존 데이터이므로 관리자만 조회.
- **보유/파기:** 상담 종료 또는 계약 완료 후 보유기간을 정책으로 정하고, 만료 데이터는 연락처 마스킹 또는 삭제 배치로 처리한다.

## 7. 단계별 로드맵

### 1단계 — 접수 채널 (선 배포)
마이그레이션 → 접수폼/랜딩 → 접수 API → 관리자 보드 → 대시보드 KPI.
- 이 단계만으로 **의뢰 접수·관리가 즉시 가능**. 유입경로 태깅 포함.

### 2단계 — 카카오톡 알림
- **선행 준비(관리자 작업):**
  1. 카카오 개발자앱에서 "카카오톡 메시지 > 나에게 보내기" 활성화, `talk_message` 스코프 추가.
  2. 알림 전용 관리자 OAuth 흐름으로 `talk_message` 동의 포함 인가 코드 발급 → refresh token 확보.
  3. refresh token은 Vercel 환경변수 또는 서버 비밀 저장소에 보관하고, 액세스 토큰 만료 시 갱신한다. 카카오가 새 refresh token을 내려주는 경우 기존 값을 교체할 운영 절차를 둔다.
- 이후 새 의뢰 시 자동 카톡 알림. 토큰 미설정·만료·전송 실패 시에는 의뢰 접수는 성공시키고, 서버 로그 또는 감사 로그에 알림 실패만 남긴다.
- **대안:** 나에게 보내기가 부담이면 카카오 알림톡(비즈채널·템플릿 심사) 또는 이메일(Resend 신규 구축)로 대체 가능.

## 8. 선행 준비물 (사용자 제공 필요)

- 크몽·재능넷·위시캣·숨고 **각 프로필 URL** (랜딩 딥링크용). 없으면 자리표시자로 두고 후속 반영.
- 각 플랫폼에서 **외부 링크/연락처 노출이 허용되는 위치** 확인 결과. 불가한 플랫폼은 관리자 수동 태깅으로 운영.
- 랜딩에 노출할 **서비스 목록/가격 정책/대표 실적** 문구(초안 제공 시 반영).
- 접수폼과 개인정보처리방침에 넣을 **상담 목적 연락처 수집·보유기간 문구**.
- (2단계) 카카오 개발자앱 접근 권한 및 관리자 카카오 계정.

## 9. 검증 시나리오 (배포 전)

1. 마이그레이션 적용 → 테이블·RLS 정상 생성.
2. 로그인 사용자 제출 → 접수 성공(201) + 관리자 보드 노출. 미로그인 시 로그인 유도.
3. 미로그인 상태에서 `?source=kmong` 유입 → 로그인 후 접수폼 복귀 → 제출 시 source 보존.
4. 본인 의뢰만 조회 가능, 타인 것 차단, 탈퇴로 `user_id`가 NULL인 의뢰는 관리자만 조회.
5. 연속 제출 시 요청 제한(429) 동작.
6. 상태 변경·메모·유입경로 보정 저장 시 감사 로그 기록, 대시보드 KPI 반영.
7. 개인정보 처리 고지 확인 시각·버전이 저장되고, 폼에 처리방침 링크가 노출.
8. `?source=kmong` 유입 → 접수 시 유입경로 자동 태깅, 보드 필터 동작. 자동 태깅 불가 건은 관리자 수동 보정.
9. (2단계) 환경변수 설정 후 신규 의뢰 → 관리자 카톡 수신 / 미설정·만료·실패 시 접수 무영향.

## 10. 향후 확장 아이디어 (선택)

- 유입경로별 전환율 리포트(플랫폼별 문의→계약 비율).
- 의뢰자용 진행상태 조회(마이페이지 내 "내 의뢰").
- 견적서/계약서 발송 및 포트원 결제 연동(선금/잔금).
- 자동 응답(접수 확인 메시지) 및 SLA 기반 리마인더.
