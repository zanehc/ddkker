## 2장. 24시간 자동화 봇 구조

> 사람 대신 24시간 작업을 처리하는 봇의 설계 원칙과 ddkkbot 아키텍처.

### 2-1. 로컬 봇 vs 클라우드 봇

| | 로컬 봇 | 클라우드 봇 |
|--|--------|-----------|
| 실행 환경 | 내 Mac/Windows | AWS, GCP, VPS |
| AI 구독 활용 | ✓ (claude, codex 직접 실행) | △ (API 키 필요) |
| 비용 | 전기료만 | 서버 월 비용 |
| 안정성 | 컴퓨터 켜야 함 | 항상 실행 |
| **추천 용도** | 번역·이미지 생성 등 AI 작업 | 단순 수집·알림 |

**결론:** AI 구독을 최대 활용하려면 로컬 봇이 유리하다.

### 2-2. ddkkbot 핵심 구조

```
daemon_service.py (데몬 관리자)
├── discord_relay.py   ← Discord WebSocket 연결, 메시지를 JSON 파일에 저장
├── slack_relay.py     ← Slack Socket Mode 연결
├── telegram_relay.py  ← Telegram 폴링
└── krc_worker.py      ← 외부 API 큐를 폴링해 AI 작업 처리 (신규 추가 방식)
```

- **daemon_service**: 모든 프로세스를 관리하는 부모. SIGINT/SIGTERM 신호 처리.
- **relay**: 각 메신저 연결을 담당. 메시지를 `discord_messages.json` 등에 저장.
- **worker**: 독립 프로세스로 실행. lock 파일로 단일 인스턴스 보장.

### 2-3. Lock 파일로 중복 실행 방지

```python
import fcntl

lock_path = BASE_DIR / ".krc_worker.lock"
lock_fh = open(lock_path, "w")
try:
    fcntl.lockf(lock_fh, fcntl.LOCK_EX | fcntl.LOCK_NB)
except OSError:
    sys.exit(0)   # 이미 실행 중이면 조용히 종료
```

> **왜?** MultiBotManager가 봇 4개를 관리할 때 각각 krc_worker를 시작하려 함.
> Lock 파일로 첫 번째만 살고 나머지는 즉시 종료.

### 2-4. 봇 자동 시작 (macOS)

```bash
# launchd plist 등록 (재부팅 후 자동 실행)
# ~/Library/LaunchAgents/com.ddkkbot.plist 생성
```

또는 Control Panel(`control_panel_macos.command`) 더블클릭으로 수동 시작/중지.

## 3장. SaaS 구축 과정

> Vercel(프론트+백엔드) + Supabase(DB) + Cloudflare R2(파일)로 월 $0~$20짜리 SaaS 인프라를 만든다.

### 3-1. 프론트엔드 — Vercel 정적 서빙

```json
// vercel.json 핵심 설정
{
  "crons": [
    { "path": "/api/notices/collect", "schedule": "0 1 * * *" }
  ],
  "routes": [
    { "src": "/api/(.*)", "dest": "api/index.py" },
    { "src": "/(.*)", "dest": "/index.html" }
  ]
}
```

**주의사항:**
- 서버리스 함수 실행 시간 한도: Hobby 60초 / Pro 300초
- 파일시스템 read-only → 파일 저장은 `/tmp` 또는 외부 스토리지(R2) 사용
- 환경변수: Vercel 대시보드 Settings > Environment Variables에 등록

### 3-2. 백엔드 — Flask + Supabase PostgreSQL

```python
# Blueprint로 API 모듈화
from flask import Blueprint
bp = Blueprint('notices', __name__)

@bp.route('', methods=['GET'])
@token_required
def list_notices(current_user):
    ...

# app.py에서 등록
app.register_blueprint(bp, url_prefix='/api/notices')
```

**Supabase 연결 (Transaction Pooler 포트 6543):**
```python
# config.py
SQLALCHEMY_DATABASE_URI = "postgresql://postgres.xxx:비밀번호@aws-1-ap-northeast-1.pooler.supabase.com:6543/postgres"
SQLALCHEMY_ENGINE_OPTIONS = {
    'pool_size': 5,
    'pool_recycle': 300,
}
```

> **왜 6543?** Session 모드(5432)는 동시 연결 제한 엄격. Transaction 모드(6543)가 서버리스에 적합.

**JWT 인증 데코레이터:**
```python
def token_required(f):
    @wraps(f)
    def decorated(*args, **kwargs):
        token = request.headers.get('Authorization', '')[7:]
        user = verify_token(token)
        if not user:
            return jsonify({'message': '인증 실패'}), 401
        return f(user, *args, **kwargs)
    return decorated
```

**멱등 마이그레이션 (데이터 유지하며 컬럼 추가):**
```python
def _run_migrations():
    migrations = [
        "ALTER TABLE bid_notices ADD COLUMN summary_ko TEXT",
        "ALTER TABLE bid_notices ADD COLUMN infographic_url VARCHAR(500)",
    ]
    with db.engine.connect() as conn:
        for sql in migrations:
            try:
                conn.execute(db.text(sql))
                conn.commit()
            except Exception:
                conn.rollback()  # 이미 있으면 무시
```

### 3-3. 파일 저장 — Cloudflare R2

| | Cloudflare R2 | AWS S3 |
|--|--------------|--------|
| 저장 비용 | $0.015/GB | $0.023/GB |
| 출력(egress) 비용 | **무료** | $0.09/GB |
| 무료 한도 | 10GB | 없음 |

```python
# utils/r2_storage.py 핵심 패턴
import boto3
from botocore.config import Config

def get_r2_client():
    return boto3.client('s3',
        endpoint_url=f"https://{ACCOUNT_ID}.r2.cloudflarestorage.com",
        aws_access_key_id=ACCESS_KEY,
        aws_secret_access_key=SECRET_KEY,
        config=Config(signature_version='s3v4', region_name='auto')
    )

def upload_file(file_obj, key, content_type=None):
    get_r2_client().upload_fileobj(file_obj, BUCKET, key,
        ExtraArgs={'ContentType': content_type} if content_type else {})

def stream_from_r2(key, content_type=None, inline=False):
    """R2 파일을 Flask Response로 스트리밍 — Vercel에서 직접 파일 저장 불가할 때 사용"""
    obj = get_r2_client().get_object(Bucket=BUCKET, Key=key)
    return Response(obj['Body'].read(), content_type=content_type or 'application/octet-stream')
```

**Vercel 파일시스템 우회 패턴:**
```
로컬 봇(krc_worker)이 이미지 생성
       ↓
boto3로 R2에 직접 업로드 (krc_worker에서)
       ↓
object key만 DB에 저장
       ↓
사용자가 이미지 요청 → /api/notices/<id>/infographic
       ↓
Vercel 서버가 R2에서 읽어서 스트리밍
```

## 4장. Google Console 로그인 시스템

> 자체 로그인 시스템 만들 필요 없이 Google OAuth + Supabase Auth로 5분 만에 구현.

### 4-1. Google Cloud Console 설정

1. [console.cloud.google.com](https://console.cloud.google.com) 접속
2. 새 프로젝트 생성
3. `API 및 서비스` > `OAuth 동의 화면` 설정 (외부 선택)
4. `사용자 인증 정보` > `+ 사용자 인증 정보 만들기` > `OAuth 클라이언트 ID`
   - 유형: 웹 애플리케이션
   - 승인된 리디렉션 URI: `https://프로젝트.supabase.co/auth/v1/callback`
5. **클라이언트 ID**, **클라이언트 보안 비밀** 복사

### 4-2. Supabase Auth 연동

Supabase 대시보드 > Authentication > Providers > Google 활성화
→ 위에서 복사한 클라이언트 ID / Secret 입력

### 4-3. 프론트엔드 로그인 버튼

```javascript
// Supabase JS SDK 활용
import { createClient } from '@supabase/supabase-js'
const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)

async function loginWithGoogle() {
    const { error } = await supabase.auth.signInWithOAuth({
        provider: 'google',
        options: { redirectTo: window.location.origin }
    })
}

// 로그인 후 JWT 가져오기
const { data: { session } } = await supabase.auth.getSession()
const token = session?.access_token   // Flask API 호출 시 Authorization 헤더에 사용
```

### 4-4. Flask에서 Supabase JWT 검증

```python
import jwt

def verify_supabase_token(token):
    try:
        payload = jwt.decode(
            token,
            SUPABASE_JWT_SECRET,
            algorithms=['HS256'],
            audience='authenticated'
        )
        return payload  # {'sub': '유저 UUID', 'email': '...'}
    except jwt.InvalidTokenError:
        return None
```

## 5장. Claude/Codex 구독 기반 자동화

> API 키 없이 월정액 구독만으로 강력한 AI를 자동화 파이프라인에 투입하는 방법.

### 5-1. Claude CLI 비대화식 실행 (번역·분석·요약)

```python
import subprocess

def run_claude(prompt: str, timeout: int = 180) -> str:
    result = subprocess.run(
        ['claude', '-p', prompt, '--output-format', 'text'],
        capture_output=True,
        text=True,
        timeout=timeout,
        stdin=subprocess.DEVNULL,   # 확인 프롬프트 차단
        cwd='/path/to/project',
    )
    if result.returncode != 0:
        raise RuntimeError(f"Claude 실패: {result.stderr[:300]}")
    return result.stdout.strip()

# 사용 예 — JSON 출력 강제
output = run_claude('''
다음 발주공고를 한국어로 번역해줘. JSON만 출력.
{"title_ko": "번역 제목", "summary_ko": "5줄 요약"}

영문 제목: Strengthening Resilience of the Agriculture Sector
''')
data = json.loads(re.search(r'\{.*\}', output, re.DOTALL).group())
```

**포인트:**
- `--output-format text`: 마크다운 없이 순수 텍스트 출력
- `stdin=subprocess.DEVNULL`: 인터랙티브 프롬프트 차단 필수
- JSON 파싱 시 `re.search(r'\{.*\}', ...)` 패턴으로 안전하게 추출

### 5-3. DB 기반 비동기 작업 큐

> AI 작업처럼 오래 걸리는 것은 큐에 넣고 별도 워커가 처리. Celery 없이 DB만으로 구현.

**테이블 설계:**
```sql
CREATE TABLE notice_tasks (
    id           SERIAL PRIMARY KEY,
    notice_id    INTEGER REFERENCES bid_notices(id),
    task_type    VARCHAR(30),   -- 'translate' | 'infographic'
    status       VARCHAR(20) DEFAULT 'pending',  -- pending→claimed→done|failed
    priority     INTEGER DEFAULT 0,   -- 숫자 작을수록 먼저
    attempts     INTEGER DEFAULT 0,
    max_attempts INTEGER DEFAULT 3,
    worker_id    VARCHAR(100),
    error        TEXT,
    result       JSONB,
    created_at   TIMESTAMPTZ DEFAULT NOW()
);
```

**워커 폴링 루프:**
```python
from concurrent.futures import ThreadPoolExecutor

def process_pending():
    tasks = get_pending_tasks(limit=30)
    groups = group_by_type(tasks)

    # translate는 3개 병렬, infographic은 1개씩 순차
    for task_type in ['translate', 'infographic']:
        max_workers = 3 if task_type == 'translate' else 1
        with ThreadPoolExecutor(max_workers=max_workers) as pool:
            list(pool.map(run_one_task, groups[task_type]))

def main():
    while True:
        count = process_pending()
        if count:
            continue          # 처리 건수 있으면 즉시 다음 사이클
        time.sleep(60)        # 없으면 60초 대기
```

**claim → process → complete 3단계:**
```
워커가 task 목록 조회 (status=pending)
       ↓ POST /api/notices/tasks/{id}/claim
status = claimed (다른 워커가 못 가져가게 잠금)
       ↓ AI 처리 (번역 or 이미지 생성)
       ↓ POST /api/notices/tasks/{id}/complete
status = done, 결과 DB 저장

실패 시: POST /api/notices/tasks/{id}/fail
attempts < max_attempts → pending으로 복귀 (자동 재시도)
attempts ≥ max_attempts → failed (더 이상 시도 안 함)
```

### 5-4. 전체 자동화 파이프라인 요약

```
[Vercel Cron 매일 KST 10시]
  → /api/notices/collect (7개 기관 병렬 수집)
  → 신규 공고 DB 저장
  → Discord 채널에 알림 발송
  → notice_tasks 큐 생성 (translate, infographic)

[로컬 ddkkbot — krc_worker 60초마다 폴링]
  → translate: claude -p "번역" → DB 업데이트
  → infographic: codex exec "$Imagegen..." → R2 업로드 → DB 업데이트
  → 각 완료마다 Discord 완료 알림

[사용자]
  → 발주공고 페이지에서 번역+인포그래픽 확인
  → 공고 삭제 시 R2 파일도 자동 삭제
```
